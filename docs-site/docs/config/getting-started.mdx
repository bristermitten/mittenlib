# Getting Started with Configs

While MittenLib provides a wide array of utilities, the Config Annotation Processor is one of its absolute killer features. It transforms simple **interfaces** into fully-functional, immutable configuration classes with serialization, deserialization, and validation built-in.

## Your First Config

Define your config structure in a simple **interface**. The processor handles everything else.

```java
import me.bristermitten.mittenlib.config.*;

@Config
public interface DatabaseConfig {
    String host();
    String username();
    String password();
    String database();
    
    default int port() {
        return 3306;
    }
    
    @Nullable
    String tablePrefix();
}
```

This single interface generates a `DatabaseConfigImpl` class that can:
- Load from YAML, JSON, or any supported format
- Validate required fields
- Provide immutable getters and copy methods
- Integrate with Guice for automatic loading

## How It Works

### 1. Define the DTO

Create an interface and annotate it with `@Config`.

```java
@Config
public interface ServerSettings {
    default String serverName() {
        return "My Server";
    }
    
    default int maxPlayers() {
        return 20;
    }
    
    default boolean whitelistEnabled() {
        return false;
    }
}
```

**Field Rules:**
- Methods are **required by default**. If a field has no `default` method and is missing from the config file, loading will fail.
- Use a `default` method to make a field optional and provide its fallback value.
- Use `@Nullable` to allow null values for optional fields.

### 2. The Generated Class

The processor creates a class named `ServerSettings` (dropping the `DTO` suffix) with:

| Feature | Generated Code |
|---------|---------------|
| **Getters** | `String serverName()`, `int maxPlayers()` |
| **Copy Methods** | `withServerName(String name)`, `withMaxPlayers(int max)` |
| **Deserialization** | Static `deserializeServerSettings(DataTree)` method |
| **Serialization** | Instance `serialize()` method |
| **Validation** | Static validation logic (if constraints are present) |
| **Standard Methods** | `toString()`, `equals()`, `hashCode()` |

### 3. Customizing the Class Name

If you don't want to use the `DTO` suffix convention, specify the name explicitly:

```java
@Config("ServerConfiguration")
public class MyConfigClass {
    String host;
}
```

This generates a class named `ServerConfiguration` instead of `MyConfigClass`.

## Loading Configs Manually

You can deserialize configs directly without Guice:

```java
// Load from a DataTree (parsed from YAML/JSON)
DataTree data = yamlLoader.load(new FileInputStream("config.yml"));
Result<DatabaseConfig> result = DatabaseConfig.deserializeDatabaseConfig(data);

result.ifOk(config -> {
    System.out.println("Connected to: " + config.host());
});

result.ifFailure(errors -> {
    System.err.println("Failed to load config: " + errors);
});
```

## Common Patterns

### Required vs. Optional Fields

```java
@Config
public interface FeatureFlags {
    // Required: must be present in config file
    boolean enabled();
    
    // Optional: uses default if missing
    default String description() {
        return "No description provided";
    }
    
    // Optional: can be null
    @Nullable
    String permission();
}
```

### Nested Configs

Configs can contain other configs. The processor recursively generates code for nested types:

```java
@Config
public interface PluginConfig {
    DatabaseConfig database();  // References another @Config interface
    FeatureFlags features();
    
    default int version() {
        return 1;
    }
}
```

This generates a `PluginConfigImpl` that automatically deserializes `database` and `features` sections.

### Collections

MittenLib supports standard Java collections:

```java
@Config
public interface Messages {
    default List<String> welcomeMessages() {
        return List.of("Welcome!", "Hello!");
    }
    Map<String, String> commandDescriptions();
    Set<String> blockedCommands();
}
```

Collections can contain primitive types, enums, or other DTOs.
